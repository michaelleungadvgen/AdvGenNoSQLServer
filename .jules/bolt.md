## 2026-10-23 - Avoid intermediate list allocations for deferred filtering pipelines
**Learning:** Returning `IEnumerable<T>` and immediately converting it to `.ToList()` inside a basic storage class (e.g. `InMemoryDocumentCollection.GetAll()`) represents a massive performance penalty when the result is directly fed into a `Where` filter anyway (`FilterEngine.Filter(documents).ToList()`). In .NET, `ConcurrentDictionary.Values` acquires locks and allocates an array to provide a moment-in-time snapshot. Iterating the dictionary directly (`foreach (var kvp in _documents) yield return kvp.Value;`) allows for truly zero-allocation lazy evaluation.
**Action:** Next time you see `.ToList()` or explicit list instantiations with `.Add()` in a data retrieval layer, look at the caller. If the caller enumerates it for filtering or projection, switch the data retrieval layer to return the lazy enumerable or an iterator block (`yield return`) to prevent O(N) memory overhead and garbage collection pressure. Additionally, avoid `.Values` on `ConcurrentDictionary` if true zero-allocation enumeration is desired.

## 2026-10-23 - Avoid redundant LINQ aggregations on ConcurrentDictionary.Values
**Learning:** Chaining multiple LINQ extension methods (like `.Sum()`, `.Average()`, `.Min()`, `.Max()`, `.ToList()`) on `ConcurrentDictionary.Values` (e.g., in `ShardingManager.cs`) is a severe performance anti-pattern. Each LINQ method triggers an independent linear scan of the entire dictionary. Crucially, in .NET, accessing `ConcurrentDictionary.Values` acquires locks across all internal buckets and eagerness allocates an array to provide a moment-in-time snapshot. Executing 7 separate LINQ queries means locking, allocating 7 arrays, and traversing the data 7 times, leading to massive CPU overhead and garbage collection pressure.
**Action:** Next time you need to compute multiple statistics or aggregations over a `ConcurrentDictionary`, eliminate the chained LINQ methods. Instead, consolidate the logic into a single `foreach` loop that iterates over the dictionary exactly once. This single pass manually accumulates the required metrics, significantly reducing memory allocations, redundant lock acquisitions, and O(N) traversals.
